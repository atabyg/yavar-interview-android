# اصلاحیه نسخه ۲ — مصاحبه یاورشهرها

## قواعد غیرقابل‌مذاکره
- نسخه موجود روی شاخه `main` دست‌نخورده می‌ماند؛ این اصلاحیه روی شاخه مستقل است.
- داده پرونده و صوت به‌صورت پیش‌فرض محلی است. هیچ sync، ارسال گزارش یا آپلود خودکار وجود ندارد.
- هوش مصنوعی ابری خاموش/غیرفعال تا وقتی کارشناس برای همان پرونده رضایت جداگانه ثبت و اقدام آگاهانه کند.
- API key فقط در حافظه درخواست می‌ماند؛ هرگز در localStorage، پرونده، گزارش، لاگ یا APK ثبت نمی‌شود. برای استفاده سازمانی، proxy امن مورد تأیید سازمان بر ارسال مستقیم ترجیح دارد.
- خروجی AI صرفاً پیشنهاد شاهد و سؤال پیگیری است. امتیاز رسمی را کد قطعی و کارشناس تعیین می‌کنند؛ AI نمی‌تواند رأی پذیرش/رد، تشخیص بالینی، دروغ‌سنجی یا تحلیل شخصیت انجام دهد.
- فقط متن قطعه‌های منتسب به مددجو به عنوان شاهد پیشنهاد می‌شود. هر شناسه قطعه باید در همان پرونده وجود داشته باشد و گوینده آن مددجو باشد.
- نتیجه نامعتبر، شناسه ناشناخته، JSON خراب یا شاهد ناسازگار رد می‌شود؛ هیچ امتیازی خودکار تغییر نمی‌کند.
- فایل PDF فقط با اقدام کاربر در share sheet یا ذخیره در فضای عمومی انتخاب‌شده صادر می‌شود. خروجی عمومی از نظر محرمانگی حساس است و باید تأیید صریح داشته باشد.
- ورود اثرانگشت فقط با AndroidX BiometricPrompt و تأیید واقعی سیستم‌عامل مجاز است. دکمه یا شبیه‌سازی جاوااسکریپت به تنهایی احراز هویت نیست.

## وضعیت منبع قواعد
در ZIP اولیه، فهرست ۲۴ سؤال وجود دارد اما فایل‌های رسمی شیوه‌نامه و راهنمای تناسب شغلی پیوست نشده‌اند. متن معیارهای رسمی ۰/۱/۲، شش‌سؤال فوری، سقف کسر فوری و شماره صفحه‌ها هنوز تأیید نشده‌اند. این بخش‌ها نباید با حدس تکمیل شوند.

## پیاده‌سازی و اعتبارسنجی
- `src/lib/interview/ai-assist.ts`: درخواست اختیاری، schema validation، فقط شاهدهای مددجو و عدم ثبت خودکار امتیاز.
- `src/lib/interview/native-exports.ts`: رابط TypeScript برای افزونه بومی؛ نیازمند پیاده‌سازی Java/Kotlin و ثبت پلاگین در Capacitor است.
- `cloudAiConsent`: پرچم رضایت مستقل از رضایت ضبط/ASR.
- `biometricEnabled`: پیش‌فرض خاموش؛ باید پس از ثبت موفق اعتبارسنجی بومی فعال شود.
- پیش از انتشار: build واقعی، تست واحد schema و scoring، تست Android 8.1 و دستگاه هدف، بررسی manifest/permissions، تست خروجی PDF فارسی، share URI و تست امنیتی ضروری است.

## نکته مهم درباره کلیدهای رایگان
«رایگان» به معنی مجاز برای داده حساس یا بدون نگهداری داده نیست. سیاست نگهداری، محل پردازش، استفاده آموزشی، قرارداد سازمانی و هزینه‌های جاری باید قبل از فعال‌سازی سرویس ابری تأیید شود. هیچ کلید مشترک یا کلید مالک مخزن در APK قرار نگیرد.
