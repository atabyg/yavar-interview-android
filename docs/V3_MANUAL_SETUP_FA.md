# راهنمای تنظیمات و قابلیت‌های خودکار نسخه ۳

## چه چیزهایی بدون تنظیم دستی اجرا می‌شوند؟
- تحلیل قاعده‌محور متن در صفحه «متن»: پس از ثبت هر قطعه، برنامه به‌صورت محلی نقش احتمالی گوینده و سؤال احتمالی مرتبط را نشان می‌دهد. این تحلیل برای کارکردن به اینترنت یا کلید API نیاز ندارد.
- بازبینی کیفیت متن در پایان: فیلدهای ناقص، شاهد ثبت‌نشده، انتساب نامطمئن گوینده، اطمینان پایین موتور گفتار (اگر ارائه شده باشد) و نشانه‌های خوداصلاحی را برای بررسی انسانی فهرست می‌کند.
- وضعیت تیک سؤال‌ها فقط بر مبنای ثبت شاهد و تأیید صریح کارشناس کامل می‌شود؛ حدس الگوریتم به‌تنهایی پاسخ رسمی یا امتیاز نمی‌سازد.

## کجا هنوز تنظیم یا اقدام دستی لازم است؟

### ۱. متن‌سازی زنده از صدا
1. در پرونده، رضایت آگاهانه و توضیح ضبط را ثبت کنید.
2. به صفحه «ضبط» بروید.
3. برای استفاده از گفتاربه‌متن مرورگر، گزینه «فعال‌سازی تشخیص گفتار مرورگر برای این جلسه» را روشن کنید.
4. بررسی کنید مرورگر/دستگاه از SpeechRecognition فارسی پشتیبانی کند؛ این قابلیت در همه مرورگرها موجود نیست و ممکن است پردازش صدا را به سرویس بیرونی بفرستد.

**مهم:** گزینه گفتاربه‌متن به‌صورت پیش‌فرض خاموش می‌ماند تا بدون رضایت آگاهانه و مجوز سازمانی داده صوتی به سرویس بیرونی ارسال نشود. این نسخه هنوز موتور گفتار فارسی کاملاً آفلاین و روی خود دستگاه ندارد. اگر گزینه را روشن نکنید، صدا ضبط می‌شود اما متن زنده خودکار ساخته نمی‌شود؛ متن باید دستی وارد یا بعداً بازبینی شود.

### ۲. استفاده از مدل زبانی ابری (اختیاری)
1. به «سؤال‌ها» و بخش «کمک هوش مصنوعی (اختیاری و ابری)» بروید.
2. پیش از استفاده، متن را بازبینی و اطلاعات شناسایی‌کننده را حذف/پوشانده کنید.
3. رضایت مستقل ارسال متن به سرویس ابری را برای همان پرونده ثبت کنید.
4. ارائه‌دهنده را انتخاب کنید و کلید API معتبر همان سرویس را وارد کنید.
5. دکمه پیشنهاد ارتباط گفتگو با سؤال‌ها را بزنید.

کلید فقط برای همان درخواست در حافظه استفاده می‌شود و در پرونده ذخیره نمی‌شود. ممکن است هزینه مصرف API داشته باشد. اشتراک ChatGPT به‌تنهایی کلید OpenAI API محسوب نمی‌شود. بدون رضایت و کلید API، این تحلیل ابری اجرا نخواهد شد. این بخش خودکارِ پس‌زمینه نیست و به اقدام صریح کارشناس نیاز دارد.

### ۳. تکمیل مشخصات پرونده از متن
در صفحه «پرونده و رضایت»، دکمه «پیشنهاد تکمیل از متن گفتگو» را بزنید. برنامه فقط از عبارت‌های صریح مانند «شماره پرونده»، «نام مددجو» یا «نام کارشناس» پیشنهاد استخراج می‌کند و فیلدهای از قبل تکمیل‌شده را جایگزین نمی‌کند. پیشنهادها را پیش از ذخیره بررسی کنید؛ استخراج خودکار از گفتار معمولی تضمین‌شده نیست.

### ۴. خروجی گزارش
- PDF: در صفحه گزارش از گزینه ذخیره/چاپ PDF استفاده کنید.
- Excel: گزینه دریافت Excel پشت تأیید PIN است.
- پیش از اشتراک‌گذاری، فهرست بازبینی نهایی را رفع یا آگاهانه بررسی کنید.

## محدودیت‌ها و هشدارهای نسخه آزمایشی
- تحلیل محلی، heuristic/قاعده‌محور است؛ مدل AI آفلاین، diarization واقعی (تشخیص هویت گوینده از صوت) یا فهم قابل اتکای معنایی را جایگزین نمی‌کند.
- تشخیص نقش و تطبیق سؤال ممکن است اشتباه باشد. متن خام، صوت و نقش گوینده باید توسط کارشناس بازبینی شوند؛ هیچ امتیاز یا تصمیم ارجاعی نباید بر اساس پیشنهاد خودکار تعیین شود.
- رمز PIN قفل برنامه، رمزنگاری داده‌های ذخیره‌شده نیست. تا زمان تکمیل رمزنگاری امن داده‌های محلی و آزمون دستگاه، اطلاعات واقعی و حساس مددجویان را در نسخه آزمایشی وارد نکنید.
- قبل از انتشار، build موفق، آزمون روی دستگاه واقعی، آزمون قطع اینترنت/مجوز میکروفون، بررسی نگهداری داده و تأیید سازمانی لازم است.

## چک‌لیست کوتاه آزمون
- [ ] بدون اینترنت، یک قطعه متنی اضافه کنید و تحلیل محلی نقش/سؤال را ببینید.
- [ ] متن مبهم را آزمایش کنید و مطمئن شوید به‌عنوان پیشنهاد نامطمئن نمایش داده می‌شود.
- [ ] بدون رضایت ابری و بدون API key، تحلیل ابری اجرا نشود.
- [ ] با رضایت و کلید آزمایشی، پاسخ نامعتبر سرویس رد شود و امتیاز رسمی تغییر نکند.
- [ ] در ضبط، گزینه گفتار مرورگر خاموش باشد و بدون فعال‌سازی، هیچ درخواست گفتاربه‌متن شروع نشود.
- [ ] فیلدهای دستی موجود هنگام پیشنهاد استخراج مشخصات تغییر نکنند.
- [ ] PDF و XLSX باز شوند و داده حساس غیرضروری در خروجی درج نشود.
